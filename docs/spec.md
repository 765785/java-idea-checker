# Windows 桌面自检网页：完整规格与规则索引

## 独立交付边界

本项目是新网页，单独位于 `windows-checker/`，不修改父目录旧网页、安装器或工作流。仅 Windows 10/11 桌面端，最低画布宽度1100px。页面可离线以 file:// 打开；通过新仓库独立发布 Pages。无第三方库、CDN、远程字体、遥测或后端。

## 接口和数据流

经典 JS脚本暴露 `ScriptTemplates.buildCheckerPs1(email)`、`buildCheckerBat(email)`、`buildRepairBat(analysis)`。修复不信任导入报告的路径或命令，每次重新采集本机。`Checker.parseResult(text)`做限长、JSON提取和结构验证，`Checker.analyze(data)`返回四态卡片、总体结论、中文总结和是否有可修复的真实故障。

单文件检测 BAT在本机运行，默认邮箱写入参数，可留空由 Read-Host询问。输出 schemaVersion=1 的 JSON到 result.txt/剪贴板/控制台。网页只读取用户主动粘贴/选择的内容，全部用 textContent渲染。超过8MB拒绝；不兼容版本拒绝；超过30分钟提示结果陈旧。

顶层字段为 meta、env、exec、javaProbe、idea、jetbrainsDirs、jetbraTrace、emailScan、errors。注册表保留用户/系统分级证据；输出 Path仅保留 Java/JDK/JetBrains相关条目；JVM设置只输出 java.home/java.version/java.vendor/os.arch，避免暴露整条库路径或用户名。路径先完成本机比较再替换用户目录前缀；邮箱只输出首字符***@域名。

## 核心行为

完整 JDK需要 java/javac文件均存在、执行成功且主版本一致。优先有效 JAVA_HOME，其次非转发器 javac对应 JDK，再选 .jdks及其他位置中的最高稳定版本。未知绿色版位置不全盘扫描。

采集 where java/javac全列表与 JVM java.home。转发器命中单独说明，不直接失败。JDK8内部 jre仅在父目录完整时映射到根目录；运行时和编译器实际来源不一致才失败，证据不足为警告。归一化包括成对引号、bin、根目录保护、大小写、斜杠、完整路径和长路径确认。旧版完整可用而另有新版只警告，不自动切换。

默认修用户环境，双级快照只用于备份核对。先预检类型、写权限、Path长度，再备份回读，写用户JAVA_HOME/Path，重读注册表，按系统Path接用户Path重建当前进程、广播、验证；失败仅恢复本次写过的用户值。不能通过伪造进程Path顺序把失败变成功。

找不到完整JDK才申请同用户UAC安装。安装子进程检查SID，拒绝跨账户。显式探测winget路径，固定官方包优先，scope不兼容才重试；搜索候选通过正则抽取并验证官方来源及JDK25。安装后重新找实际目录。无JDK且拒绝UAC保留未完成。正式复检由普通用户再次启动检测BAT。

B区固定为IDEA安装/版本→配置目录→四档邮箱证据→三步人工确认；未安装或未启动为MANUAL且不影响A。扫描新版、旧版和Toolbox配置，去重，跳过重解析点与缓存目录，扩展名限制，单文件5MB、全局3000文件。任何邮箱档位都不能证明教育包激活；插件元数据中的邮箱也不证明当前登录账户。

## 安全与权限

检测只读系统和配置文件；唯一输出为报告与剪贴板。修复不接受网页传来的任意命令。管理员子进程运行本地生成的固定逻辑。用户目录备份必须保留精确原值，报告和日志脱敏。UAC、winget联网及安装只发生在用户主动下载并运行修复BAT且无可用JDK时。
